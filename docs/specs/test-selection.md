# 仕様案: 検証コマンドの選別（test_selection）

> **棚上げ（2026-10-24）**: PR のフローを review_policy に変え、検証コマンドは変更に関係するテストだけをクライアントが選び、全体のテストはクライアントの手元で流す形になった。ワーカーが毎回すべての検証コマンドを流す前提が無くなったので、この案は実装しない。worker_review で Sandbox の中で全体のテストを流すときや、CI の手順として切り出すときの材料として残す。

ワーカーの途中の検証で、流す検証コマンドを Clef（Workers AI の決定モデル）で選び分ける仕様案（**案。未承認。実装前にユーザーの確認が要る**。決めきれない点は「未決定の事項」に列挙した）。

実測（PR #48）では、1 タスクの所要のうちテストは約 1 割、モデルの応答が約 8 割だった。節約できる上限は小さいので、**まず測れる形で入れ、効果が見えてから広げる**。選別は「安全を落とさずに待ち時間を減らす」ためのもので、最後は必ず全部流す。

## 目的

- 子が `report_completion` を呼ぶたびに全部の `verification_commands` を流している現状から、途中の反復の検証だけを、変更に関係するコマンドに絞れるようにする。
- 絞ったことで見逃した失敗の割合（見逃し率）を記録し、選別を信頼してよいかを数字で判断できるようにする。
- 入出力を CI から独立した形で定義し、将来 CI（GitHub Actions など）の手順として切り出せる余地を残す。

## 範囲と対象外

範囲:
- `task_start` の `verification_commands` を流す検証（agent の `report_completion` 時の検証）。
- 選別の入出力、ルール、Clef の使い方、失敗時の扱い、記録、`task_result` の `usage` への出力。

対象外:
- 子が bash で自分で流すテスト（子の判断に任せる。rovo は介入しない）。
- コマンドの追加・書き換え。選別は**部分集合を選ぶだけ**で、コマンドの中身（argv）を変えない。
- 個々のテストケース単位の選別（単位は常にコマンド 1 本。テストランナーの引数の組み立ては扱わない）。
- CI への組み込みの実装（「将来の拡張」に見通しだけ書く）。
- Sandbox の大きさの昇格（既存の仕組み。`origin: "verification"` で別に判断される）。

## 現状（2026-10-23 時点）

- 検証は `AgentDO` の `report_completion` の処理だけで流れる（`apps/agent/src/agent-do.ts`）。作業ツリーが clean であることを確かめ、HEAD の SHA を固定（`git checkout --detach`）してから、`verification_commands` を先頭から順に流す。1 本が失敗（終了コード非 0 かタイムアウト）したらそこで止め、残りは流さない。
- 通れば同じ SHA で完了（`completed`）にする。失敗すれば失敗した 1 本の出力を子に返す。試行は `MAX_VERIFY_ATTEMPTS`（4。最初の 1 回 + 修正 3 回）まで。
- つまり現状の検証は、**完了の申告 = 最後の検証**で、通ったらそのまま完了に確定する。「途中の反復」は、失敗して子に返された試行のこと。
- Clef は `SandboxDO` のコマンド実行の前に、Sandbox の大きさの判断（`apps/agent/src/sandbox-scale-decision.ts`）で使っている。`env.AI.run` に `@cf/cloudflare/clef-flash` を渡し、質問（指示）と state（JSON。非信頼のデータ）を分けて渡し、確率を返させる。1 回 5 秒・最大 3 回の再試行・全体 20 秒の上限があり、失敗したら今の大きさのまま続ける。

## 先行事例

同じ問題（変更に対してどのテスト・ジョブを流すか）に Jev 系のモデルを使った公開事例が 2 つある。設計はこれらを踏まえて決めた。どちらも rovo の条件（子が書いた差分、検証コマンドが任意のシェル）とは違うので、数字はそのまま信用しない。

### A. jevci（https://github.com/Ice-Hazymoon/jevci）

- ルールがジョブの集合を作り、モデル（Jev）は**確信があるときにジョブを外すだけで、足さない**。閾値は 0.2。
- ジョブごとに `checks`（何を検査し、何を検出できないか）を書いてモデルに渡す。
- コメント・整形だけの変更は、構文木で判定する（モデルを呼ばずに決まる）。
- `jevci replay` で過去の commit に当てて削減を見積もり、`jevci eval` で閾値ごとの精度を測る。
- 限界: 作者 1 人の新しいツールで、実績の積み上げが少ない。

### B. mizchi の jev-test-filter と jev-playground

- 記事: https://zenn.dev/mizchi/articles/jev-test-filter-intro 、実装の検証: https://github.com/mizchi/jev-playground/pull/5（`docs/23-task-filter.md`）。
- 依存グラフ（規則）が「走れるもの」、Jev が「走るべきもの」を決める。ゴール 1 つにつき score の質問 1 問を、1 リクエストにまとめる。
- 入力の差で精度が大きく変わる: 意図の 1 文が無いと、パスだけの判定は 0.482（コイン投げ）。diff の hunk を渡すと 0.183（誤りの指標。低いほどよい）。
- 前提の追加（このテストはあのファイルに依存する、など）は、グラフの閉包（コード）で行う。プロンプトにグラフを書くと逆効果だった。
- 閾値はコストで重み付けし、約 10 秒以下のものは無条件に流す。
- 合成データでの実測で、削減 75.8%・見逃し 0。
- 限界: 合成データでの数字で、実際のタスクの分布ではない。依存グラフを作れる言語・構成が前提。

### 設計に取り入れたこと

- Clef に渡すのは、パスだけでなく**親が書いた意図と差分の hunk** も（パスだけの判定は B で根拠のある弱点）。
- Clef は**外すだけ**（A）。足す判断はしない。足す側の保証は、ルールとコードで持つ。
- 安いコマンドは常に流す（B）。
- 測るために、過去のタスクに当てる replay を先に置く（A）。
- 取り入れなかったこと: 依存グラフの閉包（B。検証コマンドが任意のシェルで、言語に依らない汎用の形にならない。将来の拡張の候補として D に残す）、`checks` の記述（A。`verification_commands` に説明の欄が無い。D に残す）。

## 用語

| 用語 | 意味 |
|---|---|
| 検証コマンド | `verification_commands` の 1 要素（`argv`・`cwd`・`timeout_seconds`）。選別の単位 |
| 変更パス | 検証する SHA と `base_sha` の差分で変わったファイルのパス（リポジトリの根からの相対パス。リネームは新旧の両方） |
| 選別 | 変更パスと検証コマンドの一覧から、流すコマンドの部分集合と理由を決めること |
| 反復の検証 | 子が完了を申告して流れる検証のうち、選別して流す回（選別が有効なときの最初の段） |
| 確定の検証 | 全部の検証コマンドを流す回。完了の確定と、親が取り込む前の保証はこれだけが担う |
| 見逃し | 選別で飛ばしたコマンドが、同じタスクの確定の検証で失敗したこと |
| 起点ディレクトリ | コマンドの `cwd`（無ければ根）。コマンドが属するパッケージの目安として使う |

## 設計の全体

三段構えにする。順に適用し、各段の結果を記録する。

1. ルールで決める（決定的。Clef を呼ばない）。
2. 残りのコマンドを Clef に判断させる。
3. 最後の網: 確定の検証では必ず全部流す。

### 検証の流れ（`test_selection: "auto"` のとき）

1. 子が `report_completion` を呼ぶ。作業ツリーの clean と SHA の固定は従来どおり。
2. 変更パスを `git diff --name-status -z <base_sha> <sha>` で求める（信頼できる側、つまり rovo が Sandbox で実行する。子の申告は使わない）。
3. 選別する。流すコマンドの部分集合 S を決める（第 1 段と第 2 段）。
4. S を順に流す。失敗したらそこで止め、その出力を子に返す（試行を 1 つ消費する。従来どおり）。
5. S が全部通ったら、**同じ SHA のまま、S に入っていないコマンドを続けて流す**（これが確定の検証。ここで失敗すれば、飛ばしたコマンドの失敗なので見逃しとして記録し、子に返す）。
6. 全部通って初めて `completed`。

この形にすると、親が見る `completed` は常に「全コマンドが同じ SHA で通った」ことを意味し、`verified` の意味は変わらない。選別で変わるのは、**失敗する反復で、関係のないコマンド（特に重いもの）を先に流さず、失敗しそうなものから流して早く子に返す**ことだけ。通る反復の総実行量は変わらない（確定の検証で全部流すため）。節約の見込みは、失敗して直す反復が多いタスクに限る。効果は小さい可能性が高く、「記録」で測ってから判断する。

### 第 1 段: ルール（集合を作る）

入力は変更パスの一覧と検証コマンドの一覧、それに直前の実測。リポジトリの構成に依らない汎用の形で、次の順に判定する。ルールは「流す集合」を作り、**Clef はその集合から外すことしかできない**。

1. **全部流す**条件（1 つでも当たれば、Clef を呼ばず S = 全部）:
   - 依存関係の定義と lockfile が変わった: `package.json`、`*.lock`、`*-lock.*`、`pnpm-lock.yaml`、`package-lock.json`、`yarn.lock`、`Cargo.toml`、`Cargo.lock`、`go.mod`、`go.sum`、`pyproject.toml`、`uv.lock`、`requirements*.txt`、`Gemfile`、`Gemfile.lock` など。
   - ツールチェーンの設定が変わった: `mise.toml`、`.tool-versions`、`.nvmrc`、`.python-version`、`rust-toolchain*`、`Dockerfile*`、`tsconfig*.json`、`biome.json*`、`.eslintrc*`、`eslint.config.*`、各種ビルド設定（`vite.config.*`、`webpack.config.*`、`wrangler.*` など）。
   - テスト基盤が変わった: テストランナーの設定（`vitest.config.*`、`jest.config.*`、`pytest.ini`、`conftest.py`、`playwright.config.*` など）、テスト用の共通ディレクトリ（`test/support/`、`test/helpers/`、`fixtures/` などの名前の一般形）、`setup` と名のつくテスト初期化ファイル。
   - CI と検証の定義が変わった: `.github/workflows/`、`scripts/` のうち検証コマンドの `argv` に現れるファイル。
   - 検証コマンドの `argv` が直接参照しているファイルが変わった（引数に現れるパスが変更パスと一致または配下）。
   - 共有パッケージが変わった: 他の起点ディレクトリのコマンドが依存しうる共有の場所。判定は「どの起点ディレクトリにも属さないパスが変わった」「`packages/`、`libs/`、`shared/`、`common/`、`internal/` の名前の一般形の下が変わった」で近似する。
   - 変更パスや hunk が上限を超える、または変更パスの取得に失敗した。
   - 検証コマンドが 1 本だけ（選別する意味が無い）。
2. **外せない**（常に S に入れ、Clef に聞かない）:
   - 変更パスが入る起点ディレクトリのコマンド。変更パスが `cwd` の配下にあれば入れる。`cwd` が根のコマンドは常に入る（根で全部を流す 1 本だけの構成では選別が効かない。それでよい）。
   - **安いコマンド**: 直前の `durationMs` が閾値以下のコマンド（既定 10 秒の案）。流すほうが、判断するより安い（B）。直前の実測が無い（初回）コマンドは安いと見なさず、候補に回す。
3. 残りは**外す候補**として第 2 段に回る。第 2 段の既定は「流す」で、Clef が確信を持って「結果が変わらない」と答えたものだけを外す。候補が無ければ Clef は呼ばない。

ルールの一覧は設定で増やす余地を残す（D6）。コメント・整形だけの変更を構文木で判定して全部外す手は、A にある。言語ごとのパーサが要るので、最初は入れない（D3）。

### 第 2 段: Clef（外すだけ）

- 単位はコマンド（`verification_commands` の 1 要素）。候補のコマンドごとに「この変更で、このコマンドの結果は変わりうるか」を score で聞き、**ゴールごとの質問を 1 リクエストにまとめる**（B）。
- Clef に渡すのは、**親が書いた意図**（`task_start` の `title` と `instructions` の先頭。上限つき）、**変更パスの一覧**、**差分の hunk**（大きさの上限つき）、候補コマンドの `argv` と `cwd`。ファイルの全文は渡さない。
- パスだけの案は**却下**: B で、意図の 1 文が無いとパスだけの判定は 0.482（コイン投げ）だった。意図と hunk を足すと 0.183 まで下がる。パスだけでは「同じファイルの変更でも、何を変えたか」で結果が変わるかが分からない。
- 質問（指示）は rovo が固定で持つ英語の文面で、意図・パス・hunk・コマンドは state にだけ入れる。グラフや依存関係をプロンプトに書かない（B で逆効果）。依存の前提を足したいときは、ルール側（コード）で S に入れる。
- 出力は確率（「結果が変わりうる」確率）。**閾値未満のものだけを外す**。閾値は低めに置き、迷ったら流す側に倒す（A は 0.2。案: 0.2。実測で調整できるよう設定にする。D1）。確率が曖昧な帯だけ clef（大きいモデル）で聞き直す案は、最初は入れない（D2）。
- Clef は S に何も足さない。出力に S に無い `id` があっても無視する。

### 第 3 段: 最後の網

- 確定の検証（全部）を必ず通ってから `completed` にする（上の流れの 5）。
- **親が取り込む前**も全部: `task_pr_ready` と `task_pr_merge` が見る `verified` / `head_matches_verified` は確定の検証の結果だけから作る。反復の検証が通っただけでは `verified: true` にしない。
- 選別が有効でも、次のときは反復の検証を省いて、最初から全部流す: 試行が最後の 1 回（`attempts` が `MAX_VERIFY_ATTEMPTS`）のとき、前回の確定の検証が失敗していたとき（見逃しが出た直後は選別を信用しない）。

## Clef への入力と出力（案）

### 入力（state。JSON）

```json
{
  "intent": {
    "title": "請求書の端数処理を直す",
    "instructions_head": "invoice.ts の丸めを切り捨てから四捨五入に変える。API の形は変えない。"
  },
  "changed_paths": ["src/billing/invoice.ts", "src/billing/invoice.test.ts", "docs/README.md"],
  "hunks": [
    { "path": "src/billing/invoice.ts", "patch": "@@ -12,7 +12,7 @@ ...", "truncated": false }
  ],
  "candidates": [
    { "id": 0, "argv": ["pnpm", "--filter", "web", "test"], "cwd": "." },
    { "id": 1, "argv": ["pnpm", "--filter", "api", "test"], "cwd": "." }
  ]
}
```

- `candidates` は第 1 段で「外す候補」になったものだけ（外せないコマンドは入れない）。`id` は rovo が振る添字で、出力の対応づけにだけ使う。
- 上限（案。D5）: `title` 200 文字、`instructions_head` 1,500 文字、`changed_paths` 200 件・1 件 300 文字、`hunks` は合計 12,000 文字・1 ファイル 2,000 文字（超えた分は `truncated: true` で切る。**全体が上限を大きく超えるときは第 1 段で全部流す**）、`argv` は 40 個・1 個 300 文字。flash の窓（24,576 tokens）に収まる範囲にする。
- 意図の要約は、モデルでは作らない。`title` と `instructions` の先頭を切り詰めるだけ（追加の呼び出しも、追加の注入の経路も作らない。D4）。
- hunk はバイナリ・生成物・lockfile を除く（lockfile は第 1 段で全部流す側に入る）。秘密らしい値は `maskSecrets` で伏せる。

### 出力（Clef の確率を rovo が整形した結果）

```json
{
  "excluded": [{ "id": 0, "probability": 0.06 }],
  "kept": [{ "id": 1, "probability": 0.91 }],
  "model": "@cf/cloudflare/clef-flash",
  "fallback": null
}
```

- Clef が返すのは確率だけで、自由文の理由は持たない。自由文を子や親に見せない。
- 効果は `excluded`（外す）だけ。閾値以上、判断できなかったもの、候補に無いものは `kept`（流す）。
- `fallback`: Clef が失敗・時間切れ・想定外の応答のとき `"clef_failed"`。このとき `excluded` は空（全部流す）。
- 返ってきた `id` が範囲外・重複・欠けているときは、その応答全体を失敗として扱う（欠けた id は外さない）。

## 失敗時の扱い

- **fail-safe（全部流す）**。Clef の例外・時間切れ・想定外の応答・id の不整合は、すべて「何も外さず全部流す」に倒す。選別を諦めるだけで、検証自体は止めない。
- 再試行は 1 回 5 秒・最大 2 回、第 2 段全体で 10 秒まで（検証を待たせないため、Sandbox の判断（20 秒）より短くする案。D2）。
- 変更パスの取得（`git diff`）の失敗、変更パスの件数超過、`AI` のバインディング無し、`test_selection` が `"all"`: 選別せず全部流す。
- 選別の判断は検証の失敗理由にしない。Clef の失敗で試行を消費させない（判断は試行の前に済ませる）。
- 失敗は記録する（`fallback` と、`clef_failed` の件数。「記録」を参照）。

## 記録と task_result の usage

`task_result` の `usage` に、次の項目を出す案（選別が `"auto"` のとき。`"all"` のときは項目ごと省く、または `mode: "all"` だけ）。

| 項目 | 意味 |
|---|---|
| `test_selection.mode` | `"all"` または `"auto"` |
| `test_selection.rounds` | 選別した反復の検証の回数 |
| `test_selection.skipped_commands` | 反復の検証で飛ばしたコマンドの延べ数（回ごとの合計） |
| `test_selection.skipped_seconds_estimate` | 飛ばしたコマンドの直近の実測の所要の合計（実測が無ければ省く。節約の見積もり） |
| `test_selection.missed` | 見逃しの数（飛ばしたコマンドが確定の検証で失敗した回数） |
| `test_selection.missed_commands` | 見逃したコマンドの `argv` の一覧（長さを切り詰める。非信頼のデータとして囲む） |
| `test_selection.clef_failures` | Clef が失敗して全部流した回数 |
| `test_selection.cheap_commands` | 安いコマンドとして外さなかった延べ数 |
| `test_selection.decisions` | Clef の判断の記録（回ごと。変更パスと hunk の件数・大きさ、各コマンドの `id`・確率・採否・どの段で決めたか（`rule` / `cheap` / `clef` / `fallback`）、モデル名、所要） |

- 変更パス・hunk・意図そのものは `decisions` に入れない（件数・大きさ・ハッシュ程度に留める。差分に秘密に近い情報が含まれうるため。replay のデータの保存は D14）。
- 構造化イベント（ダッシュボードのコンソール）には `test_selection` のイベントを 1 回の判断ごとに積む（`selected` / `skipped` の件数と `fallback`）。
- 見逃し率 = `missed` ÷ 反復の検証で飛ばしたコマンドの延べ数ではなく、**確定の検証まで進んだ回での、飛ばしたコマンドのうち失敗したものの割合**で見る（分母は、確定の検証で実行した飛ばしたコマンドの数）。タスクをまたいだ集計は、ダッシュボードの費用の集計と同様に、後の段階で別途決める（D7）。
- 見逃しが出たときは `warnings` にも 1 行出す（親が気づけるように）。

## task_start の指定（案）

- `test_selection: "all" | "auto"`。`"all"` は現状どおり（毎回全部流す）。`"auto"` は上の三段構え。
- 既定は**最初は `"all"`**（段階 4 の実測の後に `"auto"` を既定にするかを決める。D10）。
- `verification_commands` が無い、または 1 本だけのときは、`"auto"` でも何も変わらない。
- 保存は TaskSpec に持つ（途中で変わらない）。ダッシュボードのコンソールには、`test_selection` のイベントで見える。

## セキュリティ

- 変更パス、**hunk（差分）**、コマンドの `argv` は、子（または子が読んだリポジトリの内容）が書きうる**非信頼のデータ**。意図（`title` / `instructions`）は親が書いたものだが、`instructions` に貼られた外部の文章を含みうるので、同じ扱いにする。
- 非信頼のデータは、Clef の質問（指示）に混ぜない。state の JSON の値としてだけ渡し、各値は固定の区切り（JSON の文字列）と上限で囲む。JSON は必ずシリアライザで作り、文字列の連結はしない。制御文字・非 UTF-8 のパスや hunk は第 1 段で全部流す側に倒す。上限（文字数・件数）は「Clef への入力と出力」のとおりで、超えた分は切るか、全体が大きすぎるときは全部流す。
- 変更パスと hunk は、子の申告ではなく、rovo が Sandbox で `git diff -z` から求める。
- **注入されたときの最悪の影響を、構造で小さくする**:
  - Clef の出力は確率だけ。自由文も新しいコマンドも採用しない（`id` の対応だけ）。
  - 効果は除外だけ。S に足すことも、コマンドの `argv` を変えることもできない。
  - 最後の網（確定の検証）で必ず全部流す。
  - したがって、hunk に「このテストは不要」と書いて Clef を誘導できたとしても、最悪は「途中の検証で 1 本飛ばされ、最後の網で捕まる」に限られる。`completed` と `verified` の意味は落ちない。
- 外せないもの（安いコマンド・起点ディレクトリのコマンド・全部流す条件）は、Clef を通らずコードで決まるので、注入の影響を受けない。
- 秘密らしい値は state に入れる前に伏せる（既存の `maskSecrets`）。ファイル全文は渡さない。
- Clef の呼び出しは、Sandbox の判断と同じ Workers AI のバインディングで行う。Cloudflare の外への送信は増えない。ただし hunk を渡す分、**リポジトリの差分の一部が Workers AI に送られる**ことになる（private のリポジトリの内容を含みうる）。この点は利用者が選べるよう、`test_selection` の指定で明示的に有効にする（既定は無効。D8）。
- `task_result` の `usage` に出す `missed_commands` の `argv` は、子が書いたものを含みうるので、非信頼データとして囲む（既存の `UNTRUSTED_CHILD_QUESTION` の囲みに揃える）。

## テストの方針

TDD で進める（Red → Green → Refactor）。

Unit（Workers の pool、AI は引数で差し替え）:
- ルール: 依存定義・lockfile・設定・テスト基盤・共有パッケージの変更で全部流す。変更ファイルが入る起点ディレクトリのコマンドが必ず入る。`cwd` が根のコマンドは常に入る。直前の `durationMs` が閾値以下のコマンドは常に入り、実測が無いコマンドは候補に回る。件数・hunk の超過、制御文字入りのパス、取得失敗は全部流す。コマンドが 1 本だけなら選別しない。
- Clef: 入力の JSON の組み立て（意図・hunk の上限と切り詰め、マスク、バイナリと lockfile の除外。パス・hunk・`argv`・意図に指示めいた文字列があっても、質問の側に混ざらない）。出力の整形（閾値未満だけを外す。S に無い `id` は無視。id の不整合は失敗扱い）。**Clef がどんな出力を返しても、S は全部流す集合の部分集合から外れる向きにしか変わらない**（足されない）ことを、ランダムな出力でプロパティとして確かめる。例外・時間切れ・想定外の応答で全部流す（fail-safe）。再試行の回数と期限。
- 流れ: 反復の検証で S だけ流し、通ったあとに残りを同じ SHA で流す。確定の検証で飛ばしたコマンドが失敗したら見逃しとして数え、子に返す。最後の 1 回の試行と、見逃しの直後は選別しない。`verified` は確定の検証の結果だけで決まる。`"all"` は従来と完全に同じ動き（既存のテストが無変更で通る）。
- replay: 保存済みの `verification.results` と `patch` の fixture に当てて、削減の見積もりと見逃しの数が決まった値になる（偽の Clef を使う）。結果が無い・欠けたタスクは数えずに飛ばす。
- 記録: `usage.test_selection` の各項目の算出（飛ばした数・見逃し・`clef_failures`・`decisions`）。`"all"` のときの出力。

E2E（既存の full E2E に倣う。偽の GitHub・偽のモデル（台本）・偽の Clef を使う）:
- `"auto"` で、変更に関係しないコマンドが反復の検証で流れず、確定の検証で流れて完了する。
- 偽の Clef が「飛ばす」と答えたコマンドが実際は失敗する構成で、見逃しが記録され、子に返り、直した後に全部通って完了する。
- 偽の Clef が失敗したとき、全部流れて完了する（`clef_failures` が増える）。
- 設定ファイル（lockfile）を変える台本で、Clef を呼ばずに全部流れる。
- 偽の Clef が hunk 内の「このテストは不要」という文に従う構成でも（注入の想定）、飛ばされたコマンドが最後の網で流れ、`verified` が全部の結果になる。
- `task_result` の `usage.test_selection` が上の項目どおりに返り、`verified` / `head_matches_verified` が確定の検証の結果と一致する。
- 実 Clef を使う確認は、課金と外部依存があるので受入試験（acceptance.md）に回す。

## 段階的な導入の順番

1. **仕様の確定**: この文書の未決定の事項を決める（ユーザーの確認）。
2. **replay**（A に倣う。影のモードより先）: 過去のタスクに選別を当てて、削減を見積もる。入力は、タスクごとの `verification.results`（`argv`・`exitCode`・`durationMs`）と `patch`（変更パスと hunk）、`task_start` の `title` と `instructions`。出力は、コマンドごとの採否、飛ばせた所要の合計（削減の見積もり）、**飛ばしたコマンドが過去に失敗していた件数**（見逃しの推定）。実際には Clef を呼ぶ（実費は小さい）か、記録済みの判断を使う。コードは `usage` の算出と共通にし、CI にも持っていける純粋な関数として切る。限界: 今は `verification` が最後の試行の結果だけを保存するので、過去の失敗した試行の結果は残っていない。見逃しの母数が少ない可能性が高く、`patch` を保存していないタスクは使えない。足りなければ、記録の保存（試行ごとの結果）を先に足す。
3. **影のモード**（`test_selection: "shadow"` の案。D9）: 選別は計算して記録するが、流すのは常に全部。実タスクで、飛ばせたはずのコマンドが実際に失敗したかを測る。挙動は変えないので安全。
4. **`"auto"` を明示指定で有効化**: 見逃し率と節約の見積もりを見て、閾値とルールを調整する（A の `eval` に倣い、閾値ごとの精度を replay で出す）。
5. **既定の見直し**: 見逃し率が十分低く、節約が意味のある大きさなら、既定を `"auto"` にするかを決める（D10）。
6. **CI への切り出し**: 下の「将来の拡張」。rovo の中で測ってから。

## 将来の拡張: CI（GitHub Actions など）で使う

rovo の外でも同じ手順を使えるよう、選別を CI から独立した純粋な関数として定義しておく。

入力:

```json
{
  "intent": "請求書の端数処理を直す",
  "changed_paths": ["src/a.ts", "package.json"],
  "hunks": [{ "path": "src/a.ts", "patch": "@@ ..." }],
  "commands": [
    { "id": "unit", "argv": ["pnpm", "test"], "cwd": "." },
    { "id": "lint", "argv": ["pnpm", "lint"], "cwd": "." }
  ],
  "options": { "max_changed_paths": 200, "exclude_below_probability": 0.2, "always_run_under_seconds": 10 }
}
```

出力:

```json
{
  "selected": [{ "id": "unit", "decided_by": "rule", "reason": "dependency_file_changed" }],
  "skipped": [{ "id": "lint", "decided_by": "clef", "probability": 0.05 }],
  "fallback": null
}
```

- 入出力に rovo のタスク・Sandbox・Durable Object の概念は出てこない。必要なのは変更パスの一覧とコマンドの一覧だけ。
- 見通し: 第 1 段（ルール）は依存の無い純粋関数なので、そのまま別のパッケージ（または単体の CLI / GitHub Action）に切り出せる。第 2 段は Workers AI の REST（`/ai/run`）を呼ぶ薄い層にする（CI にはバインディングが無いので、API トークンが要る。ここは未決定）。
- CI では**最後の網が違う**: プルリクエストの途中の push では選別し、マージキュー（または main への push）では全部流す、という置き方が自然。見逃しは、全部流した回で選別が飛ばしたものが失敗したかを、同じ記録の形で測る。
- 切り出す条件: rovo の中で見逃し率と節約を測り、切り出す価値があると分かってから。それまでは rovo の中だけで、入出力の形を保つ。
